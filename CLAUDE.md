# CLAUDE.md

Guidance for Claude Code working in this repo.

## Project

Godot 4.7.2 game, typed GDScript. The full spec is `docs/MASTER_PROMPT.md`. Work one phase at a time, and stop after each phase for user confirmation.

## Commands

- Godot CLI on this machine: `godot_console`
- Import / parse check: `godot_console --headless --import`
- Boot check: `godot_console --headless --quit`
- Tests: `godot_console --headless --path . -s res://tests/run_tests.gd` (add new test files to `TEST_SCRIPTS` in `tests/run_tests.gd`)
- Regenerate the UI theme after changing `InkThemeBuilder` or `InkPalette`: `godot_console --headless --path . -s res://tools/make_ui_theme.gd`
- Screenshots (needs a real renderer, so no `--headless`): `godot_console --path . -s res://tools/capture_screenshots.gd -- --out=<dir> [--size=WxH] [--tag=name]`

## Conventions

- Use static typing everywhere practical (`var x: int`, `func f() -> void`).
- Files and folders are `snake_case`; `class_name` is `PascalCase`.
- A scene's own script sits next to it (`scenes/<area>/<name>.gd`). Reusable code goes in `scripts/` (`components/`, `systems/`, `resources/`, `ui/`).
- Data assets (`.tres`) live in `data/`, and art and audio live in `assets/`.
- Systems talk through signals; avoid hardcoded cross-scene node paths.
- Avoid autoload singletons unless a later phase justifies one (document it in `docs/ARCHITECTURE.md`). The only one is `Audio` (`AudioManager`). Call `AudioManager.play(id)`; it is a no-op without the autoload, so scenes and tests must not depend on it.
- Sound effects: ids live in `data/audio/sfx_library.tres`. Placeholders come from `tools/generate_sfx.gd`. Call `AudioManager.shutdown_audio(tree)` before quitting, or Godot reports still-playing streams as leaked.
- Art is drawn by code (`scripts/visuals/`, style guide `docs/ART_BIBLE.md`), except the user-approved original painted samurai layers and title portrait in `assets/art/samurai/`. Preserve their transparent alpha and embedded prompt provenance. Colours come from `InkPalette`; UI colours come from the theme's variations, not per-node overrides.
- Third-party assets (audio so far) are allowed ONLY if their licence permits commercial use. Record every third-party asset in `docs/ASSET_LICENSES.md` (what, author, licence, where it is used; the game never shows or loads it and exports must not include it), in the same commit as the asset; add it to `docs/CREDITS.md` (the Credits screen) only if its licence requires attribution. The Credits screen shows only the creator line and the Momiziba music line, which its licence REQUIRES: never remove or shorten that credit, and add nothing else (no Kenney, Pixabay or Sonniss lines, no mention of AI or Claude). Never add an asset whose licence you cannot confirm. Keep only the files the game uses (cut long recordings with `tools/make_sfx_ogg.py`), and never commit `.zip` archives (they are git-ignored).
- Text files use LF line endings (enforced by `.gitattributes`).
- Commit `*.uid` files; ignore `.godot/`.
- Stored node references (targets, projectile sources) can be freed at any time. Check `is_instance_valid(member)` on the member itself before using it or passing it on: passing a freed object into a typed parameter is a script error. Clear the reference when it's invalid.
- Battlefield, upgrade menu and main menu expose `save_path` (and battlefield/main menu also expose `settings_path`). Automated runs must point them at test files under `user://` so they never touch the player's real save or settings.
- Godot 4.7 has built-in classes with common names (e.g. `VirtualJoystick`). A `class_name` that collides is a parse error, so check before naming a class.
- Touch input: widgets call `Input.action_press/release` on the existing Input Map actions. Gameplay reads input state only. Events injected with `Input.parse_input_event` use window pixels, not canvas units.
- Stages: Region 1 stages 2–5 are generated by `tools/make_region_1.py`; edit its table, re-run it, then import. Stage ids are save keys: never rename them.
- Balance changes: measure with `tools/balance_sim.gd` (bot and allies-only modes) before and after; it uses its own save under `user://balance_sim`.
- Never report test or validation results that weren't actually run. The test runner fails any test that logs an engine or script error.
